# Intelligence Base MVP

> 아직 교과서가 없는 분야(초기 기술·기술 융합)의 지식과 아이디어를 **찾고, 써 보고, 검증하는 놀이터**.
> 사람도 쓰고, AI도 MCP로 직접 조회한다.

이 문서는 개발 입문자 기준으로 썼어. 순서대로 읽으면 **무엇을 만들었고, 각 파일이 무슨 일을 하고, 다음에 뭘 해야 하는지** 알 수 있어.

---

## 1. 실행하기 (설치 필요 없음)

필요한 것: **Python 3.10 이상** 하나뿐이야. 외부 패키지를 하나도 안 썼어.

```bash
cd intelligence-base
python seed.py                 # 예시 데이터 만들기 (가상의 예시 6개 주장, 6명)
python -m ib.server            # 웹 서버 켜기
```

브라우저에서 http://127.0.0.1:8000 을 열면 돼.
`단백질 후보를 실험 전에 빨리 줄이고 싶어` + 분야 `protein-design`으로 검색해 보면 세 칸이 모두 채워지는 걸 볼 수 있어.

테스트 실행:

```bash
python -m unittest discover tests -v     # 25개 테스트
```

외부 선행 자료(arXiv) 검색까지 켜려면 인터넷이 되는 환경에서:

```bash
IB_PRIOR_ART=arxiv python -m ib.server       # Windows PowerShell: $env:IB_PRIOR_ART="arxiv"; python -m ib.server
```

## 2. 전체 구조 한눈에 보기

```
사람(브라우저) ──HTTP──▶ server.py ─┐
                                   ├─▶ service.py ─▶ search.py / matching.py / models.py
AI(Claude 등) ──MCP───▶ mcp_server.py ┘        │
                                               ▼
                                            db.py ─▶ ib.sqlite3 (파일 하나짜리 DB)
                         service.py ─▶ relatedness.py (기술 간 거리) / prior_art.py (외부 선행 자료)

schema/claim.schema.json = 다른 제품과 데이터를 주고받기 위한 공통 규격(프로토콜)
```

**핵심 아이디어:** 입구는 두 개(사람용 웹, AI용 MCP)지만, 실제 기능은 `service.py` 한 곳에 있어. 그래서 두 입구가 항상 똑같이 동작해.

## 3. 파일별 역할과 기능

### `schema/claim.schema.json` — 프로토콜(연동 규격)
- **역할:** "지식 한 단위는 이런 모양이다"를 정한 약속. 다른 서비스가 이 규격대로 데이터를 보내거나 받으면 서로 연동돼.
- **담는 정보:** 주장 본문, 검증 상태, 적용 맥락(분야·조건), 계보(`derived_from`), 기여자, 시도 기록.
- **쓰인 기술: JSON Schema.** JSON 데이터의 모양을 정의하는 국제 표준. 검사 도구가 많아서 "이 데이터가 규격에 맞나?"를 자동으로 확인할 수 있어.

### `ib/models.py` — 규칙
- **`compute_status()`:** "사용이 곧 검증" 규칙. 시도 기록을 보고 상태를 정해.
  - 시도 없음 → **미검증**
  - 시도한 사람이 1명뿐이거나 결과가 엇갈림 → **검증 중**
  - 서로 다른 2명 이상, 성공 70% 이상 → **재현됨**
  - 서로 다른 2명 이상, 실패 60% 이상 → **반박됨**
  - 한 사람이 여러 번 눌러도 **마지막 결과 하나만** 세. 혼자 도배하는 걸 막기 위해서야.
- **`validate_*_input()`:** 들어온 데이터가 올바른지 검사해. 이상한 데이터가 DB에 들어가는 걸 막는 문지기 역할이야.
- 숫자 기준(2명, 70%, 60%)은 파일 맨 위에 모아 뒀어. 바꾸고 싶으면 거기만 고치면 돼.

### `ib/db.py` — 저장소
- **역할:** 사람·주장·시도·기여를 저장하고 꺼내.
- **테이블 4개:** `people`(사람), `claims`(주장), `trials`(써 본 기록), `contributions`(누가 어떤 기여를 했나)
- **주요 기능**
  - `add_claim()`: 주장을 저장하고 작성자 기여를 기록해. 다른 주장에서 파생됐다면 **원래 작성자에게도 '파생' 기여를 자동 기록**해. 내 아이디어 위에 누가 쌓으면 나도 공로를 받는 구조야.
  - `add_trial()`: 시도를 저장하고 **상태를 자동으로 다시 계산**해.
  - `lineage()`: 계보를 따라가서 조상(기반한 것)과 후손(파생된 것)을 찾아.
  - `portfolio()`: 한 사람의 기여 기록과 요약(작성 수, 재현된 수, 검증 시도 수, 남이 내 위에 쌓은 수)을 만들어.
- **쓰인 기술: SQLite.** 파일 하나로 된 데이터베이스야. 서버 설치가 필요 없어서 MVP에 딱 맞아. **SQL**은 데이터베이스에 "이 조건의 데이터를 줘" 하고 요청하는 언어야.

### `ib/search.py` — 검색과 세 칸 분류
- **역할:** 질문과 비슷한 주장을 찾아서 세 칸으로 나눠.
  - **검증됨:** 재현된 것 중 관련 있는 것
  - **유사 맥락 해법:** 내 분야가 아닌 **다른 분야**에서 나온 비슷한 해법(융합의 씨앗). 탐색용이라 기준을 조금 느슨하게 뒀어.
  - **미검증 최신:** 최근 30일 안에 올라온 미검증·검증 중 아이디어. 최신순으로 정렬해.
  - 반박된 건 숨기고, 몇 개 숨겼는지만 알려줘.
- **쓰인 기술: TF-IDF + 코사인 유사도.**
  - TF-IDF는 "이 글에 자주 나오면서 다른 글엔 드문 단어"를 중요하게 보는 방식이야.
  - 코사인 유사도는 두 글을 숫자 목록(벡터)으로 바꾸고, 방향이 얼마나 비슷한지를 0~1로 재는 방법이야.
  - 한국어는 조사 때문에 같은 단어도 달라 보여서("단백질을", "단백질은") **두 글자씩 자른 조각**도 함께 비교해.
  - **한계:** 단어가 겹쳐야만 찾아. "실험 횟수 줄이기"와 "후보 필터링"처럼 뜻은 비슷한데 단어가 다르면 놓쳐. → 7번의 개선 1순위.

### `ib/matching.py` — 사람 매칭
- **`match_people()`:** 문제에 맞는 사람을 찾아. 결과를 **같은 분야**와 **다른 분야(융합 후보)**로 나눠서 보여줘.
  - 점수 = 역량 텍스트 유사도 + 같은 분야면 +0.2 + 검증 활동이 많으면 최대 +0.1
  - `why` 항목에 점수가 왜 그렇게 나왔는지 같이 담아. 추천 이유를 설명할 수 있어야 믿을 수 있으니까.
- **`suggest_verifiers()`:** 주장을 검증해 줄 만한 사람을 추천해. 작성자 본인과 이미 시도한 사람은 빼. **검증도 매칭 문제로 푼다**는 설계를 그대로 구현한 부분이야.

### 원조·중복은 어떻게 다루나 (핵심 원칙)
플랫폼은 **누가 원조인지 판정하지 않아.** 대신 세 가지만 해.
1. **기록:** 누가 무엇을 언제 올렸는지 남긴다.
2. **판단 재료 제공:** 먼저 올라온 비슷한 주장과 외부 선행 자료를 보여준다.
3. **작성자의 선택을 기록:** 작성자가 직접 "같아 / 발전시켰어 / 달라"를 고르고, 그 선택을 지울 수 없게 남긴다.

### 올리기 전 확인 흐름 (`service.precheck()` + 화면의 "아이디어 올리기" 탭)
1. 작성자가 주장을 쓰고 **"비슷한 게 있는지 확인하기"**를 누른다.
2. 서버가 기존 주장과의 유사도를 계산해서, 기준(0.1) 이상인 것을 최대 5개 보여준다. 각 후보에는 **누가, 언제 먼저 올렸는지**가 같이 표시된다.
3. 외부 선행 자료(arXiv)도 함께 보여준다. 켜져 있을 때만.
4. 작성자가 후보마다 관계를 고른다.
   - **같아(same):** 새로 올리지 않는다. 서버가 `409` 응답으로 막고, 기존 주장에 써 본 결과를 남기도록 안내한다. 같은 주장이 여러 개로 흩어지면 검증 기록도 흩어지니까.
   - **발전시켰어(derived):** 계보(`derived_from`)에 자동으로 연결되고, 원작자에게 '파생' 기여가 기록된다.
   - **달라(distinct):** 계보에는 안 넣고, "작성자가 다르다고 판단함"만 기록으로 남긴다. 나중에 다른 사람이 보고 판단할 수 있게.
5. 이 선택은 프로토콜의 `links` 필드로 저장된다.

**유사도는 후보를 고르는 데만 쓰고, 판정에는 쓰지 않아.** 숫자가 높다고 자동으로 중복 처리하면, 다른 분야로 옮긴 융합 아이디어(가장 가치 있는 것)를 중복으로 잘못 막게 돼.

### `ib/prior_art.py` — 외부 선행 자료 검색
- **역할:** 플랫폼 안에서는 처음이어도 세상엔 이미 있을 수 있으니, arXiv 논문을 찾아서 "이미 알려진 것일 수 있음" 링크를 보여줘.
- **제공자(Provider) 구조:** `ArxivProvider`, `NullProvider`(꺼짐)를 갈아 끼울 수 있어. 특허 DB나 Semantic Scholar를 추가하려면 `search()` 함수를 가진 클래스를 하나 더 만들면 돼.
- **안전장치:** 외부 검색이 실패해도 글 올리기는 막지 않아. 화면에서는 `http(s)` 링크만 표시해.
- **쓰인 기술:** arXiv 공개 API, Atom(XML) 파싱(`xml.etree`), `urllib`
- **한계:** arXiv는 영어 검색이라 한국어 주장은 영어 태그가 있어야 찾아져. 실서비스에선 LLM으로 주장을 영어 검색어로 바꾸는 단계가 필요해.

### `ib/relatedness.py` — 기술 간 거리
- **역할:** 주장 상세 화면의 "가까운 기술" 목록을 만든다. 세 가지 신호를 합쳐.
  - **의미 (0.5):** 글이 얼마나 비슷한가 (지금은 TF-IDF, 나중에 임베딩)
  - **계보 (0.3):** 조상(기반한 주장·자료)이 얼마나 겹치나
  - **함께 시도 (0.2):** 같은 사람들이 둘 다 써 봤나
- **자카드 유사도:** 두 집합의 겹침을 재는 방법이야. "둘 다 가진 것의 수 ÷ 둘 중 하나라도 가진 것의 수". 예를 들어 A를 시도한 사람이 {민안, 다나}, B를 시도한 사람이 {다나, 준}이면 1 ÷ 3 = 0.33이야.
- 결과마다 세 신호 값과 **다른 분야인지 여부**를 같이 보여줘. 다른 분야인데 가까운 기술이 융합 후보야.
- 가중치(0.5/0.3/0.2)는 임시값이야. 사용자가 실제로 클릭하고 채택한 데이터가 쌓이면 그걸로 조정해야 해.

### `ib/service.py` — 기능 묶음
- **역할:** 위 기능들을 조합해서 "검색", "주장 등록", "시도 기록" 같은 완성된 기능으로 제공해. 입력 검사도 여기서 해.
- 웹 서버와 MCP 서버가 둘 다 이 파일만 불러 써.

### `ib/server.py` — 웹 API 서버
- **역할:** 브라우저나 다른 프로그램이 HTTP 주소로 기능을 쓰게 해줘.
- **쓰인 기술: REST API, JSON, `http.server`(파이썬 내장)**
  - REST API는 "주소 + 동사"로 기능을 부르는 약속이야. `GET`은 가져오기, `POST`는 만들기.
  - 응답 코드: 200 성공, 201 생성됨, 400 입력 오류, 404 없음.
  - `Access-Control-Allow-Origin` 헤더로 **다른 사이트에서도 호출할 수 있게** 열어 뒀어. 연동을 위해서야.

| 주소 | 기능 |
|---|---|
| `GET /api/claims?q=문제&domain=분야` | 세 칸 검색 |
| `POST /api/claims/precheck` | 올리기 전 확인: 먼저 올라온 유사 주장 + 외부 선행 자료 |
| `POST /api/claims` | 아이디어 올리기 (`links`로 관계 선택 전달, "같아"면 409) |
| `GET /api/claims/{id}/related` | 가까운 기술 (의미·계보·함께 시도 신호) |
| `GET /api/claims/{id}` | 주장 상세 (프로토콜 형식) |
| `POST /api/claims/{id}/trials` | 써 본 결과 기록 → 상태 자동 갱신 |
| `GET /api/claims/{id}/lineage` | 계보 |
| `GET /api/claims/{id}/verifiers` | 검증자 추천 |
| `GET /api/people`, `POST /api/people` | 사람 목록 / 등록 |
| `GET /api/people/{id}/portfolio` | 기여 기록 |
| `GET /api/match/people?q=...` | 사람 매칭 |
| `GET /schema/claim` | 프로토콜 규격 파일 |

### `ib/mcp_server.py` — AI 연동 통로
- **역할:** Claude 같은 AI가 이 지식 베이스를 직접 검색하게 해줘. AI가 학습하지 못한 최신 지식을 **검증 상태와 함께** 읽어 가는 통로야.
- **제공하는 도구 4개:** `search_knowledge`(검색), `get_claim`(상세), `check_existing`(새 아이디어를 제안하기 전에 기존 주장·선행 자료 확인), `report_trial`(써 본 결과 기록)
- 도구 설명에 **"미검증은 미검증이라고 밝혀라"** 같은 안내를 넣어 뒀어. AI가 미검증 아이디어를 사실처럼 말하는 걸 줄이기 위해서야.
- **쓰인 기술: MCP(Model Context Protocol), JSON-RPC, 표준입출력(stdio)**
  - MCP는 AI 앱과 외부 도구를 잇는 공개 규격이야.
  - JSON-RPC는 "이 함수를 이 인자로 실행해 줘"를 JSON으로 주고받는 방식이야.
  - AI 앱이 이 프로그램을 실행하고, 키보드 입력/화면 출력 통로로 메시지를 한 줄씩 주고받아.
- **Claude Desktop에 연결하는 법:** 설정 파일(`claude_desktop_config.json`)에 아래를 추가해. 경로는 네 컴퓨터에 맞게 바꿔.

```json
{
  "mcpServers": {
    "intelligence-base": {
      "command": "python",
      "args": ["-m", "ib.mcp_server"],
      "cwd": "/절대경로/intelligence-base",
      "env": { "IB_DB": "/절대경로/intelligence-base/ib.sqlite3" }
    }
  }
}
```

### `web/index.html` — 화면
- **탭 4개:** 지식 찾기(세 칸 + 상세: 조건·계보·시도 기록·검증자 추천), 아이디어 올리기, 사람 찾기(같은 분야/다른 분야), 기여 기록
- 상세 화면의 **"써 봤더니 됐어 / 안 됐어"** 버튼이 바로 "사용이 곧 검증" 장치야.
- `?q=...&domain=...` 주소로 열면 바로 검색돼서 검색 결과 링크를 공유할 수 있어.
- **쓰인 기술: HTML(구조), CSS(디자인), JavaScript(동작).** `fetch()`로 서버 API를 부르고 결과를 화면에 그려. `esc()` 함수로 사용자가 입력한 글을 안전하게 바꿔서, 악성 스크립트가 끼어드는 공격(XSS)을 막아.

### `seed.py` / `tests/test_core.py`
- `seed.py`: 시연용 **가상** 데이터 생성. 계보 연결, 재현됨·검증 중·미검증·반박됨 상태가 모두 들어 있어.
- `tests/test_originality.py`: 새로 추가한 기능의 테스트 10개. 사전 확인에서 먼저 올린 사람 표시, "같아" 선택 시 차단, "발전" 선택 시 계보·공로 연결, "달라" 선택 시 기록만 남김, 세 신호 계산, arXiv 응답 해석, 네트워크 실패 시 안전 처리를 확인해.
- `tests/test_core.py`: 자동 테스트 15개. 상태 규칙, 세 칸 분류, 반박 숨김, 계보와 파생 공로, 입력 검사, 검증자 제외, 다른 분야 매칭, HTTP 흐름, MCP 통신을 확인해. **코드를 고친 뒤 이걸 돌려서 다 통과하면 기존 기능이 안 깨졌다는 뜻이야.**

## 4. 지금 MVP가 증명하는 것

1. 지식 한 단위를 **검증 상태 + 맥락 + 계보 + 기여**와 함께 다루는 규격이 실제로 돌아간다.
2. **써 본 결과가 쌓이면 상태가 자동으로 바뀐다** (미검증 → 검증 중 → 재현됨/반박됨).
3. 검색이 **검증됨 / 다른 분야 해법 / 미검증 최신** 세 칸으로 나뉜다.
4. 남이 내 아이디어 위에 쌓으면 **나에게도 공로가 기록된다.**
5. 같은 데이터를 **사람(웹)과 AI(MCP)가 함께 쓴다.**

## 5. 추가로 구현해야 할 것 (우선순위 순)

### 1단계: 실사용 전에 꼭 필요한 것
| 항목 | 왜 필요한가 | 어떻게 |
|---|---|---|
| **로그인/인증** | 지금은 누구나 아무 사람인 척할 수 있어. 검증 기록을 믿을 수 없어 | GitHub·ORCID 로그인(OAuth). 연구자는 ORCID가 신뢰도에 좋아 |
| **의미 기반 검색** | 단어가 달라도 뜻이 같으면 찾아야 해. 유사 맥락 칸의 품질이 여기서 결정돼 | 임베딩 모델로 글을 벡터로 바꾸고 벡터 DB(pgvector 등)에 저장 |
| **어뷰징 방지** | 친구끼리 성공을 눌러주면 가짜 '재현됨'이 생겨 | 검증자의 과거 신뢰도로 가중치 부여, 같은 그룹끼리 반복 검증 탐지, 증거(코드·데이터 링크) 첨부 필수화 |
| **프레임워크·DB 교체** | 내장 서버와 SQLite는 동시 사용자가 많으면 버티지 못해 | FastAPI + PostgreSQL. `service.py` 구조 덕분에 입구와 저장소만 바꾸면 돼 |
| **공식 MCP SDK** | 규격이 업데이트되면 직접 만든 구현은 따라가기 어려워 | `mcp` 파이썬 패키지로 교체. 원격 접속(HTTP 방식)도 지원 |

| **원조 판별 고도화** | 지금은 단어 유사도로 후보를 뽑아서 표현이 다르면 놓쳐 | ① 임베딩으로 후보 추출 ② LLM이 주장을 방법·문제·결과로 쪼개 비교해서 "같음/전이/충돌/대안"을 **제안** (판정은 여전히 작성자) ③ 한국어 주장을 영어 검색어로 바꿔 외부 검색 |
| **위조 불가능한 기록** | DB 관리자가 시각·작성자를 바꿀 수 있어 | 기록마다 해시 체인으로 엮고, 하루치 지문을 외부 타임스탬프 서비스에 등록 |
| **이의 제기 기록** | "이건 내 주장과 같다"는 지적을 남길 곳이 없어 | 증거 링크를 붙인 이의 제기를 지울 수 없는 기록으로 남기고 주장 옆에 표시 |

### 2단계: 놀이터다운 기능
- **재현 증거 첨부:** 시도 기록에 코드 저장소, 노트북, 데이터 링크를 붙이게 해. "됐어" 버튼만으로는 약해.
- **조건별 검증:** 지금은 상태가 주장 하나에 하나뿐이야. "A 조건에선 재현, B 조건에선 실패"처럼 **조건마다 따로 상태**를 두면 맥락 기반 매칭이 정확해져.
- **도전 과제:** "이 기법을 X 문제에 적용해 보기" 같은 작은 과제를 올리고, 사람을 매칭해 주는 기능.
- **알림:** 내 분야에 새 아이디어가 올라오거나, 내가 검증자로 추천되면 알려주기.
- **자동 입문 가이드:** 재현된 주장들을 계보 순서로 엮어서 AI가 "이 분야 처음 온 사람용 지도"를 만들어 주기.
- **반박 이유 구조화:** 실패 기록에 "조건이 달랐다 / 재현 불가 / 주장 자체가 틀림"을 구분하기.

### 3단계: 프로토콜과 연동
- **공로를 외부 표준으로 내보내기:** 기여 기록을 Hypercerts 형식으로, 계보를 W3C PROV 형식으로 변환해서 다른 서비스에서도 인정받게 하기.
- **가져오기 연동:** arXiv 논문, GitHub 저장소, Hugging Face 모델을 `derived_from`으로 자동 연결하기.
- **규격 공개:** 실제 사용이 확인되면 `claim.schema.json`을 별도 저장소로 공개하고 버전 관리(0.1 → 1.0)하기. 다른 서비스가 이 형식으로 내보내고 가져가게 만드는 게 목표야.
- **분산 저장 검토:** 한 회사가 데이터를 쥐고 있으면 표준이 되기 어려워. AT Protocol처럼 각자 데이터를 들고 있는 구조를 장기적으로 검토하기.
